# Review checklist

Written for: you, when a result comes back.
Use it when: you must decide whether to accept, fix or send back what a helper returned.

> Guidance lines start with `>`. Delete them when you copy this.
> Decide how much to check before you open the result, using the definition of done you wrote at the start.

## 1. Before you open it

- Task: ____
- Result received on: ____
- Brief and definition of done in front of me: [ ] yes
- How much will I check: [ ] everything  [ ] a sample  [ ] signals only
- What a mistake would cost if it got through: ____
- Time I will give this review: ____

> Check more as the cost of a mistake rises. Where one wrong item would be costly, such as a wrong amount in a payment, check every one.

## 2. Checks for every result

- [ ] It answers what the brief asked, not a nearby question
- [ ] Everything in the definition of done is present
- [ ] Sources are named, and I opened at least ____ of them
- [ ] Assumptions are listed, and I agree with them
- [ ] Gaps are admitted: it says what it could not do or confirm
- [ ] Nothing extra was changed, sent or deleted
- [ ] Nothing private ended up where it should not be
- [ ] A confident tone is not standing in for evidence

## 3. For a batch: review in layers

> Look at a little of everything cheaply, then at a few risky items carefully.

1. Skim for shape, not content. Are the items about the same length? Are any empty or repeated?
2. Read a sample in full, chosen by rule (every ____th item) and not by eye.
3. Add the awkward ones on purpose: the longest, the shortest, the oldest, the one with the strangest source.
4. Tally what you found by kind of problem. A kind that shows up twice is probably in the rest too.
5. Decide from what you found. A clean sample earns a lighter look at the rest. A messy one means fix the brief and rerun, not patch item by item.

- Rule used: ____
- Items read: ____ of ____
- Problems found, by kind: ____

> Sampling finds patterns, not every single error.

## 4. A diff or list of changes

Files, a document with tracked changes, or a code change.

- [ ] I compared the helper's summary with the actual changes, and they match
- [ ] The number of items touched is what I expected: ____
- [ ] Nothing was touched that the brief put out of scope
- [ ] Each deletion and rename is intended
- [ ] Settings, configuration and permissions did not change unnoticed
- [ ] Each change is small enough to understand on its own
- [ ] Checks or tests were run, and I can see the output
- [ ] I can undo it: ____ (how)

> For code, read by commit from oldest to newest, and read the tests first.

## 5. A summary or written report

- [ ] I found each claim and marked which ones have a source
- [ ] I opened the source for at least three claims, and it says what the summary says
- [ ] Names, numbers and dates match the inputs
- [ ] Where sources disagree, the report shows both
- [ ] The most important point is at the top
- [ ] I asked what a careful person would have added, and what is missing
- [ ] Wording that sounds sure is backed by something I can check
- [ ] Quotes are exact when compared with the source

## 6. A spreadsheet or table

- [ ] I recomputed one total by hand
- [ ] I counted the rows, and they match the input
- [ ] Units, currencies and dates are consistent within each column
- [ ] I clicked into several formulas, and they refer to the cells I expect
- [ ] I tried one edge case: an empty cell, a zero, the largest value, a repeated row
- [ ] There are no hidden rows, columns or sheets that I did not ask for
- [ ] Totals do not count anything twice
- [ ] The source and the date of the data are written on the sheet

## 7. A translation

- [ ] Numbers, dates, names and units match the original
- [ ] The count of pieces matches (sections, items, lines)
- [ ] I translated key passages back, using a different tool or person, and the meaning held
- [ ] Terms I fixed in the brief are used the same way everywhere
- [ ] A reader whose first language it is read the parts that matter, for ____ minutes
- [ ] I looked hardest where readers act: buttons, prices, warnings, dates, instructions
- [ ] Names that should stay untranslated were left alone

## 8. Decision

- [ ] Accept
- [ ] Accept with my edits: ____
- [ ] Send back for one round of rework
- [ ] Reject, and do it another way

Rework note, if sending back:

- What was wrong, by kind: ____
- What to change: ____
- What to keep as it is: ____
- What to add to the brief next time: ____
